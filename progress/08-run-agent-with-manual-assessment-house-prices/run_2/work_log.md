## Iteration 2
- **Timestamp**: 2026.05.19 14:00:00
- **Train Log MSE**: 6.39e-03
- **Test Log MSE**: 1.68e-02
- **Intended change**: Improve feature representation and remove outliers
- **Reasoning**: The train/test gap (4.44e-03 vs 1.69e-02, ~3.8x) still indicates overfitting. Three categories of improvements: (1) **Ordinal encoding** — quality features (ExterQual, BsmtQual, KitchenQual, etc.) have a natural ordering (Ex=5 > Gd=4 > TA=3 > Fa=2 > Po=1 > None=0). One-hot encoding discards this ordering, forcing the model to learn it from data. Similarly, BsmtFinType (GLQ>ALQ>BLQ>Rec>LwQ>Unf), GarageFinish (Fin>RFn>Unf), and BsmtExposure (Gd>Av>Mn>No) are ordinal. (2) **Feature engineering** — domain-relevant composite features: TotalSF (GrLivArea + TotalBsmtSF), TotalBath (all baths), HouseAge/RemodelAge, IsRemodeled, TotalPorchSF, and binary indicators (HasGarage, HasBsmt, HasFireplace, Has2ndFlr, HasPool). Also interaction features: OverallScore (OverallQual × OverallCond) and LivingQualSF (GrLivArea × OverallQual). (3) **Outlier removal** — 2 known outliers with GrLivArea > 4000 and unusually low SalePrice (184k and 160k) that skew the model. (4) **Drop low-information high-missingness features** — PoolQC (99.5% missing), MiscFeature (96%), Alley (94%), Fence (80%) add noise and expand one-hot dimensions without signal.
- **Code diff**: Added `_apply_ordinals()` with quality/finish mapping dicts, `_engineer_features()` with 13 new composite features, `_remove_outliers()` filtering GrLivArea > 4000 with low log(SalePrice), added DROP_COLUMNS set for PoolQC/MiscFeature/Alley/Fence

## Iteration 3
- **Timestamp**: 2026.05.19 18:00:00
- **Train Log MSE**: 6.06e-03
- **Test Log MSE**: 1.56e-02
- **Intended change**: Replace single XGBoost model with a stacked ensemble of XGBoost + LightGBM + CatBoost, blended via Ridge regression on cross-validation out-of-fold predictions
- **Reasoning**: Iteration 2's test Log MSE barely improved (1.69e-02 → 1.68e-02) despite ordinal encoding, feature engineering, and outlier removal. A single XGBoost model has hit a ceiling. The key improvement is **model diversity via stacking**: (1) **Three diverse base learners** — XGBoost (depth-wise growth, conservative), LightGBM (leaf-wise growth, handles high-cardinality features well, slightly deeper at max_depth=4/num_leaves=15), CatBoost (ordered boosting, reduces prediction shift, depth=4). Each model has different inductive biases and makes different errors. (2) **5-fold cross-validation blending** — each base model's out-of-fold predictions are collected as meta-features for a Ridge meta-learner. This avoids overfitting the meta-model since training data for the meta-learner comes from predictions on held-out folds. (3) **Ridge meta-learner with alpha=1.0** — simple linear combination of base predictions with L2 regularization; learns optimal weights without overfitting the 3 meta-features. (4) **All base models retrained on full data** for final inference, ensuring no wasted training samples. Preprocessing (ordinal encoding, feature engineering, outlier removal) is unchanged from Iter 2.
- **Code diff**: Replaced `self.model` (single XGBRegressor) with `self._base_models` (list of 3 models) and `self._meta_model` (Ridge). Added `_make_xgb()`, `_make_lgbm()`, `_make_catboost()` factory functions. `fit()` now performs 5-fold CV to generate out-of-fold meta-features, then fits Ridge on meta-features. `predict()` stacks base model predictions and feeds to Ridge. Updated `save()`/`load()` to persist base models and meta-model instead of single model.

## Iteration 4
- **Timestamp**: 2026.05.19 22:00:00
- **Train Log MSE**: 5.21e-03
- **Test Log MSE**: 1.58e-02
- **Intended change**: Four improvements targeting overfitting, feature representation, ensemble diversity, and meta-learner robustness
- **Reasoning**: Iteration 3 improved test Log MSE from 1.68e-02 to 1.56e-02, a solid gain from stacking. However, the train/test gap (6.06e-03 vs 1.56e-02, ~2.6x) still indicates room to reduce overfitting. Key changes: (1) **Target encoding for high-cardinality categoricals** — Neighborhood (25 values), Exterior1st/2nd (15+), MSSubClass (16), MSZoning, SaleType, SaleCondition, Condition1/2, HouseStyle produce sparse one-hot columns when one-hot encoded. Target encoding replaces each category with its mean log(SalePrice), giving the model a direct numerical signal. The original categorical column is still one-hot encoded alongside, so the model has both representations. (2) **Added sklearn GradientBoosting as 4th base model** — increases ensemble diversity. GB uses max_depth=3, subsample=0.7, max_features=0.5, similar regularization to XGBoost but with a different implementation (histogram-based vs exact splits). OOF scores show all 4 models competitive (0.0120–0.0127). (3) **Inverse-MSE weighted average meta-learner** instead of Ridge — with only 4 meta-features, Ridge can overfit or produce negative weights. A weighted average where each model's weight is proportional to 1/OOF_MSE is simpler, always positive, and naturally upweights better-performing models. (4) **Early stopping for CatBoost** — added early_stopping_rounds=50 in CV folds so CatBoost doesn't overfit unused iterations.
- **Code diff**: Added `TARGET_ENCODE_COLUMNS` list (10 high-cardinality categoricals). Added `_apply_target_encoding_train()` and `_apply_target_encoding_test()` methods that compute per-category mean log(SalePrice) during training and apply mapping at test time. Added `_make_gb()` factory for sklearn GradientBoostingRegressor. Replaced Ridge meta-learner with inverse-MSE weighted average (`_meta_weights` computed from OOF scores). Added `gb_fold` to the 5-fold CV loop as 4th base model. CatBoost folds now use `early_stopping_rounds=50`. Updated `save()`/`load()` to persist `_target_encode_maps`, `_global_mean`, and `_meta_weights` instead of `_meta_model`.

## Iteration 5
- **Timestamp**: 2026.05.20 10:00:00
- **Train Log MSE**: 5.23e-03
- **Test Log MSE**: 1.56e-02
- **Intended change**: Fix three issues from Iteration 4 that caused test Log MSE regression (1.56e-02 → 1.58e-02): unsupervised target encoding overfitting, missing early stopping for XGBoost/LightGBM in CV folds, and redundant one-hot columns for target-encoded features
- **Reasoning**: Iteration 4's test Log MSE regressed from 1.56e-02 to 1.58e-02 despite the intent to improve. Three likely causes: (1) **Unsmoothed target encoding** — raw per-category mean log(SalePrice) overfits rare categories (e.g., a Neighborhood with 2 samples gets an extreme encoded value that doesn't generalize). Fixed with **smoothing**: each category's encoding is a weighted average of the category mean and the global mean, where the weight depends on sample count via `smoothing = 1 / (1 + exp(-(count-1)/10))`. Categories with <10 samples get pulled strongly toward the global mean; categories with 100+ samples retain their raw mean. This is a standard target encoding best practice that prevents leakage from rare categories. (2) **No early stopping for XGBoost and LightGBM in CV folds** — both models were running all 3000 iterations on each fold without validation-based early stopping. This means OOF predictions come from overfitted models, inflating meta-feature noise. CatBoost already had early_stopping_rounds=50 in folds (added in Iter 4). Now XGBoost and LightGBM also stop early when validation loss stops improving, producing less overfitted OOF predictions. (3) **Dropping original categorical columns for target-encoded features** — Iteration 4 kept the original categorical columns (one-hot encoded) alongside their target-encoded versions, adding ~100+ sparse binary columns. This doubled the feature space for these columns and created redundancy (the one-hot columns can reconstruct the same information as the target encoding, but noisily). Now the original categorical columns are dropped after target encoding is applied, keeping only the dense _TE column. This dramatically reduces dimensionality and noise. Note: for the full-data retrain at the end of fit(), XGBoost does NOT use early stopping (no eval_set available), preserving the original behavior.
- **Code diff**: (1) Replaced `_apply_target_encoding_train()` — now uses smoothed encoding with `TE_SMOOTHING_MIN_SAMPLES=10`; smoothing weight = `1/(1+exp(-(count-1)/10))`; blended = global_mean*(1-smoothing) + category_mean*smoothing. (2) Changed `_make_xgb(early_stopping=False)` — parameterized factory; CV folds use `_make_xgb(early_stopping=True)` with `early_stopping_rounds=50` in constructor; full-data retrain uses `_make_xgb()` without early stopping. (3) Added `lgbm_early_stopping` import and `lgbm_early_stopping(50, verbose=False)` callback in LGBM CV folds. (4) After target encoding is applied, drop the 10 original categorical columns (`TARGET_ENCODE_COLUMNS`) before one-hot encoding the remaining categoricals, eliminating ~100+ redundant one-hot columns.

## Iteration 6
- **Timestamp**: 2026.05.20 14:00:00
- **Train Log MSE**: 7.28e-03
- **Test Log MSE**: 1.55e-02
- **Intended change**: Improve ensemble diversity and regularization to break the 1.56e-02 plateau
- **Reasoning**: Iteration 5 matched Iter 3's test Log MSE (1.56e-02) but did not improve further. The ensemble of 4 tree-based boosting models (XGB, LGBM, CatBoost, GB) has limited diversity — all are gradient boosted decision trees with similar inductive biases, so they make correlated errors and the meta-learner can't extract much benefit from combining them. Three changes: (1) **Replace sklearn GB with ElasticNet** — a linear model with L1+L2 regularization has fundamentally different inductive bias from tree models. It captures linear relationships directly (which trees approximate poorly), and its errors will be uncorrelated with tree model errors. ElasticNet with alpha=0.001, l1_ratio=0.5 is lightly regularized to avoid overfitting while still benefiting from feature selection via L1. Requires StandardScaler since linear models are sensitive to feature scales. (2) **Increase KFold from 5 to 10** — with only 1168 training samples, 10-fold CV gives more robust OOF meta-features (each fold uses 1051 train / 117 validation vs 934/234). More folds means each sample's OOF prediction is based on a model trained on more data, reducing the variance of meta-features. (3) **Tune XGBoost regularization** — slightly increased `min_child_weight` from 5→6 and `reg_lambda` from 1.5→2.0 to further reduce XGBoost's tendency to overfit. The train Log MSE increased from 5.23e-03 to 7.28e-03 (less overfitting), which is expected and desirable. The ElasticNet OOF score (0.012954) is slightly worse than tree models but adds genuine diversity to the ensemble. Meta weights remain well-distributed (0.24-0.26 range).
- **Code diff**: (1) Replaced `GradientBoostingRegressor` import with `ElasticNet` from sklearn.linear_model and `StandardScaler` from sklearn.preprocessing. (2) Replaced `_make_gb()` with `_make_en()` returning ElasticNet(alpha=0.001, l1_ratio=0.5, max_iter=10000). (3) Added `self._scaler = None` to `__init__`. (4) In `fit()`: fit StandardScaler on training features, create `X_scaled` DataFrame; in CV folds, ElasticNet uses scaled data; full-data retrain uses scaled data for ElasticNet. (5) In `predict()`: explicitly call each base model with appropriate data (unscaled for trees, scaled for ElasticNet) instead of list comprehension. (6) Changed `N_FOLDS` from 5 to 10. (7) Changed XGBoost `min_child_weight` from 5→6 and `reg_lambda` from 1.5→2.0. (8) Updated `save()`/`load()` to persist `_scaler`.
